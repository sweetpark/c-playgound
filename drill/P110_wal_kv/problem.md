# P110 · wal_kv — 로그(WAL)와 체크포인트로 크래시에서 살아남는 키-값 저장소

> 예상 시간: 60분 (이 시리즈에서 가장 큰 문제). `test.c` 의 `[6]`(체크포인트 직후 크래시)과 `[7]`(찢어진 꼬리)을 먼저 읽자.

## 요구사항

메모리에 있는 데이터는 프로세스가 죽으면 사라진다. 그래서 **변경을 먼저 로그 파일에 쓰고**, 가끔 **전체를 스냅샷으로** 남긴다. 다시 켜면 `스냅샷 + 그 뒤의 로그`로 복원한다. 이것을 가장 작게 만든다. 자세한 형식은 `kv.h` 맨 위에 있다.

| 함수 | 하는 일 |
|---|---|
| `kv_open(dir)` | **복구**: 스냅샷 읽기 → 로그 재생 → 깨진 꼬리 잘라내기 → 이어쓰기 |
| `kv_put` / `kv_del` | 로그에 쓰고 fsync **한 다음에** 메모리에 반영 |
| `kv_get` / `kv_count` / `kv_lsn` | 조회 |
| `kv_checkpoint` | 스냅샷을 임시 파일에 완성 → `rename` → 그다음에 로그 비우기 |
| `kv_close` | 메모리 해제만 (체크포인트 안 함) |

## 지켜야 할 것

| # | 규칙 | 이유 |
|---|---|---|
| 1 | **로그 먼저, 메모리 나중** | 메모리만 바뀐 채 죽으면 변경이 흔적 없이 사라진다 |
| 2 | 로그 한 줄에는 **crc** 가 붙는다. 틀린 줄을 만나면 **거기서 재생을 멈춘다** (뒤에 올바른 줄이 있어도 버린다) | 중간이 깨졌다면 그 뒤를 믿을 수 없다 |
| 3 | 줄바꿈 없이 끝난 줄은 쓰다 만 것이다 → 버린다 | 끝까지 쓰였다는 보장이 없다 |
| 4 | 버린 꼬리는 파일에서 **잘라낸다** | 안 자르면 다음 기록이 깨진 줄 뒤에 붙어서 같이 망가진다 |
| 5 | `lsn <= 지금 lsn` 인 기록은 **건너뛴다** | 체크포인트에서 로그를 비우기 전에 죽으면 이미 스냅샷에 들어간 옛 로그가 남는다 |
| 6 | `lsn` 이 건너뛰면 거기서 멈춘다 | 중간이 빠진 로그를 이어 붙이면 상태가 틀어진다 |
| 7 | 스냅샷은 **임시 파일에 다 쓰고 END 를 적은 뒤** `rename`. END 없는 스냅샷은 무시 | `rename` 은 원자적이라 "반쯤 쓴 스냅샷"이 정식 이름으로 보이지 않는다 |
| 8 | 로그는 스냅샷이 자리 잡은 **뒤에** 비운다 | 순서가 바뀌면 중간에 죽을 때 데이터가 사라진다 |

> 7, 8번 일부(체크포인트 한가운데서 죽는 상황)는 시험이 프로세스를 중간에 끊을 수 없어서 **자동으로 검사하지 못한다.** 그래도 지켜야 하는 규칙이다 — `NOTE.md` 에 설명이 있다.

## 입출력 예시

```
put a 1 / put b 2 / put c 3      → lsn 3
(kv_close — 프로세스가 죽었다고 치자)
kv_open                          → count 3, lsn 3 (로그만으로 복원)
kv_checkpoint                    → snapshot 생성, wal.log 는 0바이트
put d 4                          → lsn 4, wal.log 는 1줄
```
