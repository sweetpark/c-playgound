# P100 · sd55 dangerfunc — 위험하다고 알려진 함수 사용 — fork 치환으로 치환

## 요구사항

별도 프로세스에서 값을 계산한 뒤 부모는 자신의 상태를 그대로 유지해야 한다.
- 자식 프로세스의 작업이 부모의 메모리에 영향을 줘서는 안 된다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **fork 치환으로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| (해당 없음) | — | `vfork()` 함수 자체의 계약(주소 공간 공유)이 결함이다 |

## 시그니처

```c
int demonstrate_vfork_bad(void);
int demonstrate_fork_good(void);
```

## 입출력 예시

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `vfork()`로 자식 생성 후 자식이 스택 변수 수정 | **부모의 값까지 `999`로 바뀜**(취약점 재현) | `vfork()`는 `exec`/`_exit` 전까지 자식이 부모와 **같은 주소 공간**을 쓴다고 명세돼 있다 |
| 같은 상황(Good, `fork()`) | 부모 값은 `100`으로 그대로 유지 | `fork()`는 자식에게 독립된(Copy-on-Write) 주소 공간을 준다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

`make P100` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- vfork는 자식이 부모와 주소 공간을 공유해 부모의 스택 변수까지 바꿔버려야 한다(취약점 재현)
- fork는 자식이 독립된 복사본에서 동작해 부모 값이 그대로 보존돼야 한다
