# P078 · sd33 nosalt — 솔트 없이 일방향 해쉬 함수 사용 — 사용자별 난수 솔트로 치환

## 요구사항

여러 사용자의 패스워드를 해시로 저장한다.
- 서로 다른 사용자가 같은 패스워드를 쓰더라도, 저장된 해시값은 서로 달라야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **사용자별 난수 솔트로 치환**.

## 시그니처

```c
unsigned hash_no_salt_bad(const char *pw);
unsigned hash_with_salt_good(const char *pw, unsigned salt);
```

## 입출력 예시

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| alice, bob이 둘 다 `hunter2` 사용 | **완전히 같은 해시값** | 솔트가 없어 입력이 같으면 출력도 같다 — 레인보우 테이블 대조 한 번으로 둘 다 뚫린다 |
| 같은 상황(Good, 서로 다른 솔트) | 서로 다른 해시값 | 사전 계산된 테이블이 무력화된다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P078` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- hunter2
- Bad는 두 사용자가 같은 패스워드를 쓰면 완전히 같은 해시가 나와야 한다(레인보우테이블 취약점 재현)
- Good은 같은 패스워드라도 솔트가 다르면 해시도 달라져야 한다(사전 계산 공격 무력화)
- 같은 패스워드+같은 솔트는 항상 같은 해시가 나와야 한다(검증 가능해야 함)
