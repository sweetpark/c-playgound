# P047 · sd02 resinj — 자원 삽입 — 화이트리스트 범위 검사로 치환

## 요구사항

환경변수 문자열(`env_val`)을 받아 서비스가 리슨할 포트 번호를 결정한다.
- 허용 포트는 `3000`~`3003` 4개뿐이다.
- 범위를 벗어나면 기본값 `3000` 을 쓴다(연결 실패 대신 안전한 기본값으로 대체).

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **화이트리스트 범위 검사로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `env_val` | 외부(환경변수) | 소켓 `bind()` 포트 인자 |

## 시그니처

```c
int parse_port_bad(const char *env_val);
int parse_port_good(const char *env_val);
```

## 입출력 예시

| 입력 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `"3002"` (정상) | 3002 | 정상 동작 |
| `"22"` | **22** | SSH 등 다른 서비스 포트를 그대로 점유하려 든다 |
| `"99999"` | **99999** | `uint16_t` 범위(0~65535)를 넘어 소켓 바인딩 시 오동작·크래시 소지 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P047` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 SSH 포트도 그대로 받아들여야 한다(취약점 재현)
- Bad는 유효 범위 밖 포트도 그대로 반환
- 정상 포트는 그대로 반환
- Good은 범위 밖이면 기본값(3000)으로 대체
- Good은 65535 초과도 기본값으로 대체
- Good도 허용 범위 안 값은 그대로 통과
