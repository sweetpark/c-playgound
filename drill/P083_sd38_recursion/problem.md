# P083 · sd38 recursion — 제대로 제어되지 않은 재귀 — 깊이 제한 동반으로 치환

## 요구사항

정수 `n`의 계승을 재귀로 계산한다.
- 비정상적으로 큰 `n`이 들어와도 프로세스가 죽어서는 안 된다.
- 실패는 반드시 호출자에게 알려야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **깊이 제한 동반으로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `n` | 외부 입력(요청 파라미터) | 재귀 호출 깊이를 그대로 결정 |

## 시그니처

```c
long fac_bad(int n);
int fac_good(int n, long *out);
```

## 입출력 예시

| 입력(`n`) | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 아무 값이나(종료 조건 자체가 없음) | **스택 오버플로우로 프로세스 크래시**(`expect_crash`가 감지) | `n`이 계속 감소해 음수로 끝없이 내려가도 멈출 조건이 코드에 없다 |
| `n = 100000`(Good) | **정상적으로 `-1` 반환**(크래시 없음) | 깊이 제한(`MAX_DEPTH`)에 도달하면 재귀를 스스로 멈추고 실패를 호출자에게 알린다 |
| `n = 5`(Good) | `120` | 정상 범위는 base case로 정확히 종료 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P083` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 종료 조건이 없어 스택이 고갈될 때까지 재귀하다가 크래시해야 한다(취약점 재현)
- 정상 범위(n=5)는 성공해야 한다
- 5! = 120 이어야 한다
- Good은 깊이 제한을 넘으면 크래시 대신 통제된 실패(-1)를 반환해야 한다
