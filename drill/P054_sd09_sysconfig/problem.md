# P054 · sd09 sysconfig — 시스템 또는 구성 설정의 외부 제어 — 인덱스 간접참조로 치환

## 요구사항

서비스가 사용할 FTP 포트를 결정한다.
- 허용되는 포트는 미리 정의한 3개(기본 `21`, 대체1 `2121`, 대체2 `8021`)뿐이다.
- 외부에서는 "몇 번째 대체 포트를 쓸지" 인덱스만 전달받아야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **인덱스 간접참조로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `portStr` | 외부(명령줄 인자/설정 요청) | 서비스 포트 설정값 |

## 시그니처

```c
int resolve_service_port_bad(const char *portStr);
int resolve_service_port_good(int index);
```

## 입출력 예시

| 입력 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `"21"` (정상) | 21 | 정상 동작 |
| `"22"` | **22** | SSH 등 이미 쓰이는 포트와 충돌시켜 서비스 거부(DoS)를 유발할 수 있다 |
| `"0"` | **0** | 예약 포트(0)를 그대로 받아 시스템이 예기치 않게 동작할 수 있다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P054` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 외부 입력을 그대로 서비스 포트로 써서 임의 포트를 지정할 수 있어야 한다(취약점 재현)
- 0번 포트 같은 비정상 값도 그대로 통과
- 정상 포트 문자열도 그대로 반환
- Good은 범위 밖 인덱스를 거부해야 한다
- 음수 인덱스도 거부
- 인덱스 0은 기본 포트(21)
- 인덱스 1은 대체 포트(2121)
