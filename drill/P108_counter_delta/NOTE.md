# NOTE · P108 counter_delta (풀고 난 뒤에 보세요)

**원본 글**: 「[모니터링] 누적 카운터와 게이지 — 차분으로 속도를 만드는 통계」

**함정 요약**
- 차이를 `unsigned` 로 빼서 음수가 "엄청 큰 양수"가 됨 — `5 - 4294967290` 은 `value < last` 를 먼저 가르고 계산해야 한다
- WRAP 과 RESET 을 구분하지 않음 — 재시작인데 WRAP 으로 계산하면 건수가 수십억으로 부풀고, 반대면 실제 증가량을 놓친다 (이 문제의 구분 규칙은 휴리스틱이다. 실제 시스템에서는 재시작 사실을 따로 알 수 있으면 더 정확하다)
- "이전 값"을 갱신하지 않음 — 재시작 후 다음 구간 차이가 또 음수가 된다
- 평균의 평균 — `(10+40)/2 = 25`. 건수로 가중해야 37
- 건수 합 0 으로 나눔 — 데이터 없는 구간은 NaN/크래시 대신 0.0
- `sum_check` 의 `diff` 를 부호 없는 형으로 두고 "음수면 중복 카운트"로 판단 — 음수가 영영 안 나온다

**한 줄 설명 연습**: "세는 쪽은 누적값만 올리고, 읽는 쪽이 차이로 구간 값을 만든다. 되돌아간 값(재시작·오버플로)과 평균 합산을 처리하지 않으면 통계가 조용히 틀린다." 를 내 말로 쓴다.
