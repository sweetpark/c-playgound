# NOTE · P106 shm_probe (풀고 난 뒤에 보세요)

**원본 글**: 「[OS] 공유메모리 세그먼트 — 크기·key·권한·수명과 삭제」 (학습 노트)

**함정 요약**
- `shmat` 실패를 `NULL` 로 검사 — 실패값은 `(void *)-1`. 그대로 쓰면 곧바로 크래시
- 붙은 프로세스가 죽으면 세그먼트도 같이 사라진다고 착각 — **안 사라진다.** `nattch` 만 줄어든다. 그래서 `ipcs -m` 에 `nattch 0` 인 세그먼트가 쌓인다
- `IPC_RMID` 를 부르면 바로 사라진다고 착각 — 붙어 있으면 `SHM_DEST` 상태로 남고, 마지막 `shmdt` 에서 사라진다. `ipcs -m` 의 `status` 열에 `dest` 로 보인다
- `fork` 뒤 `nattch` 를 잘못 셈 — 부모가 붙여 둔 세그먼트는 **자식에게 상속**되어 `nattch` 가 자동으로 하나 더 늘어난다 (`exec` 하면 떨어진다)
- `shmdt` 를 안 부름 — 프로세스가 끝나면 커널이 정리하지만, **오래 도는 프로세스**에서는 매핑이 쌓인다
- `size` 를 키우려고 같은 key 로 `shmget` — 이미 있으면 더 큰 size 는 `EINVAL`. 크기를 바꾸려면 지우고 새로 만든다

**한 줄 설명 연습**: "공유메모리는 프로세스의 것이 아니라 커널의 것이라, 만든 프로세스가 죽어도 남고, 지우려면 `IPC_RMID` 후 모두가 떼야 한다." 를 내 말로 쓴다.
