# P106 · shm_probe — 공유메모리 세그먼트는 언제 사라지나

> 예상 시간: 25분. `test.c` 의 `[3]`(자식이 붙은 채 죽음)과 `[4]`(삭제 예약)를 먼저 읽어 보자.

## 요구사항

공유메모리는 "프로세스 둘이 같은 메모리를 본다"가 전부가 아니다. **언제 만들어지고, 누가 붙어 있고, 언제 사라지는지**를 모르면 장애 때 `ipcs -m` 의 숫자를 읽을 수 없다. 관찰 도구 일곱 개를 만든다.

| 함수 | 하는 일 |
|---|---|
| `shm_make(size)` | `IPC_PRIVATE` 세그먼트 생성 |
| `shm_nattch(id)` | 붙어 있는 프로세스 수 (`shmctl(IPC_STAT)` 의 `shm_nattch`) |
| `shm_marked_dead(id)` | `SHM_DEST` 비트가 켜졌나 (삭제 예약 상태) |
| `shm_map(id)` / `shm_unmap(p)` | `shmat` / `shmdt` (실패하면 `NULL` / `-errno`) |
| `shm_remove(id)` | `IPC_RMID` (삭제 **예약**) |
| `shm_exists(id)` | 아직 존재하나 |

## 지켜야 할 것

| # | 규칙 | 이유 |
|---|---|---|
| 1 | `shmat` 의 실패값은 `NULL` 이 아니라 `(void *)-1` | 이걸 `NULL` 과 비교하면 실패를 놓친다 |
| 2 | 붙은 채로 프로세스가 죽으면 커널이 **자동으로 뗀다** (`nattch` 감소). 하지만 **세그먼트는 남는다** | 만든 쪽이 죽어도 공유메모리는 안 사라진다. 정리는 명시적으로 |
| 3 | `IPC_RMID` 는 "지워라"가 아니라 **"마지막 사람이 떼면 지워라"** | 붙어 있는 동안은 계속 읽고 쓸 수 있다 (`SHM_DEST`) |
| 4 | 아무도 안 붙었을 때의 `IPC_RMID` 는 즉시 삭제 | |
| 5 | 이미 지워진 id 에 대한 조회/삭제는 실패 | `EINVAL`/`EIDRM` |

## 제약

- `solution.c` 만 고친다. 경고 0, ASan/UBSan 0. 시험이 끝나면 만든 세그먼트가 하나도 남아 있지 않아야 한다 (`ipcs -m`).
