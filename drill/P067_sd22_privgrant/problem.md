# P067 · sd22 privgrant — 잘못된 권한 부여 — 그룹별 UID 테이블로 치환

## 요구사항

사용자의 그룹(관리자/일반/게스트)에 따라 부여할 UID를 결정한다.
- 관리자 그룹만 UID 0(root)을 받을 수 있다.
- 모르는 그룹은 어떤 권한도 받으면 안 된다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **그룹별 UID 테이블로 치환**.

## 시그니처

```c
int resolve_uid_bad(int isCorrectUser);
int resolve_uid_good(group_t group);
```

## 입출력 예시

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 정상 로그인(그룹 무관) | **UID 0(root) 부여** | "정상 유저인지"만 확인하고 어떤 그룹인지는 안 본다 |
| 게스트 그룹 정상 로그인(Good 대상) | 게스트 전용 UID | 그룹에 맞는 권한만 부여 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P067` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 정상 로그인만 하면 손님 계정도 root(0)를 받아야 한다(취약점 재현)
- 인증 실패는 권한이 없어야 한다
- Good은 게스트 그룹에 root(0)를 주면 안 된다
- Good은 모르는 그룹은 권한 없음으로 처리해야 한다
- 관리자 그룹만 root(0)를 받아야 한다
- 일반 그룹은 일반 UID를 받아야 한다
