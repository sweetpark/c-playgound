# P104 · alog_ring — 비동기 로거: 큐가 가득 차면 기다리지 않고 버린다

> 예상 시간: 40분. 한 번에 안 풀려도 괜찮다 — 먼저 `test.c` 의 `[3]`, `[5]` 를 읽고 무엇을 요구하는지 보자.

## 요구사항

서비스 스레드가 로그를 남길 때마다 **디스크 쓰기를 기다리면**, 디스크가 느려지는 순간 서비스 전체가 멈춘다.
그래서 로그는 **큐에 넣기만 하고 바로 돌아오고**, 별도의 **소비 스레드**가 큐에서 꺼내 실제 목적지에 쓴다.
다만 큐는 한정된 크기라서 **소비가 생산을 못 따라가면 큐가 찬다.** 이때 정책은 하나다:

> 서비스를 멈추느니 **로그를 버린다.**

`alog.h` 의 다섯 함수를 구현한다.

| 함수 | 하는 일 |
|---|---|
| `alog_create(capacity, sink, ctx)` | `capacity` 칸 큐와 소비 스레드를 만든다. 잘못된 인자면 `NULL` |
| `alog_write(a, line)` | 줄을 **복사해** 큐에 넣는다. 가득 차면 **기다리지 않고** 버리고 `ALOG_FULL` |
| `alog_is_full(a)` | "가득 참" 상태. **한 번 켜지면 빈 칸이 `capacity/10` 이상(최소 1) 생길 때 꺼진다** |
| `alog_stats(...)` | 받은 줄(`enq`), 꺼낸 줄(`deq`), 버린 줄(`dropped`), 쌓인 줄(`used`) |
| `alog_destroy(a)` | 큐에 남은 줄을 **전부 내보낸 뒤** 소비 스레드를 join 하고 메모리를 해제 |

## 지켜야 할 것

| # | 규칙 | 이유 |
|---|---|---|
| 1 | `alog_write` 는 **절대 블록하지 않는다** | 로그 때문에 서비스가 멈추면 본말이 뒤집힌다 |
| 2 | 줄은 **복사**해서 보관한다 | 호출자의 버퍼는 곧 다른 내용으로 바뀐다 |
| 3 | sink 는 **락 밖에서** 부른다 | sink 가 느린 동안 다른 스레드의 `write` 가 같이 막힌다 |
| 4 | 받은 줄은 **받은 순서대로** 나간다 | 로그의 시간 순서 |
| 5 | `destroy` 는 남은 줄을 **다 내보낸 뒤** 끝낸다 | 안 그러면 마지막 로그(보통 종료 직전의 원인)가 사라진다 |
| 6 | FULL 해제에 **여유(히스테리시스)** 를 둔다 | 한 칸 비었다고 바로 풀면 켜졌다 꺼졌다를 초당 수천 번 반복한다 |
| 7 | 여러 스레드가 동시에 `write` 해도 안전 | 서비스 스레드는 여러 개다 |

## 입출력 예시 (`capacity = 10`, sink 가 멈춰 있을 때)

| 상황 | 결과 |
|---|---|
| 100줄을 연달아 `write` | 10~11줄만 `ALOG_OK`, 나머지는 `ALOG_FULL`. 걸린 시간은 거의 0 |
| 그때 `alog_is_full` | 1 |
| sink 를 풀고 `destroy` | 받은 줄(10~11줄)이 받은 순서대로 전부 나간다. 버린 줄은 돌아오지 않는다 |

(10 이 아니라 11 이 될 수 있는 이유: 소비 스레드가 첫 줄을 이미 꺼내서 sink 안에서 멈춰 있기 때문이다.)
