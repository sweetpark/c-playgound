# P058 · sd13 writebeforestart — 버퍼 시작 지점 이전에 쓰기 — 하한 검사로 치환

## 요구사항

크기 10짜리 배열에 `count` 개의 값을 **역순**(뒤 인덱스부터)으로 채운다.
- `count` 가 배열 크기(10)보다 많을 수 있다 — 이 경우 안전하게 실패 처리해야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **하한 검사로 치환**.

## 시그니처

```c
void write_before_start_bad(int count);
int write_before_start_good(int count, int *out_arr, size_t arr_size);
```

## 입출력 예시

| `count` | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 10 (정상, 배열 크기와 동일) | 정상 동작 | 인덱스가 정확히 9→0으로 끝난다 |
| 11 (배열 크기 초과) | **버퍼 시작 이전 쓰기로 크래시** | 인덱스가 0 아래로 내려가 `words[-1]` 에 쓴다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P058` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 토큰이 배열 크기보다 많으면 버퍼 시작 이전에 써서 크래시해야 한다(취약점 재현)
- 배열 크기와 같은 개수는 크래시 없이 정상 동작
- Good은 배열 크기를 넘는 개수를 거부해야 한다
- 정상 개수는 성공해야 한다
- 역순으로 채워진 마지막 값이 정확해야 한다
