# NOTE · P109 load_shed (풀고 난 뒤에 보세요)

**원본 글**: 「[HTTP] 과부하 제어 — 서버가 스스로 요청을 거절하는 법」

**함정 요약**
- 구간이 바뀔 때 `count` 를 0 으로 안 돌림 — 한 번 한도가 차면 영원히 거절
- 새 구간 조건을 `w != window` 로 씀 — 시계가 뒤로 가면 센 개수를 잊고 한도가 뚫린다 (`>` 여야 한다)
- 거절하면서 `count` 를 올림 — 한도가 찬 뒤 거절이 쌓여 다음 구간에도 영향
- `seq % 100 <= cut` — 100개 중 `cut + 1` 개가 거절된다 (경계 오류)
- 백오프에 `base << attempt` 를 그대로 사용 — `attempt >= 64` 에서 정의되지 않은 동작, 그 전에도 `long` 오버플로로 음수 대기
- 상한을 마지막에만 적용 — 중간에 이미 넘쳐 있다. 두 배 하기 **전에** 비교한다
- `rnd % 1000` — `rnd = 1000` 일 때 상한 `d` 에 닿지 않는다 (`% 1001`)
- 지터 퍼센트를 범위 검사 없이 사용 — `150` 이면 `lo` 가 음수

**참고(이 문제의 한계)**: 고정 구간은 경계에 몰리면 0.2초에 한도의 2배가 통과한다 (`[3]`). 슬라이딩 윈도우나 토큰 버킷은 이를 줄이지만 구현과 비용이 늘어난다. 앞단에서 값싸게 쓰려면 고정 구간으로 충분한 경우가 많다.
