# P109 · load_shed — 서버가 스스로 요청을 거절하는 부품 세 개

> 예상 시간: 40분. `test.c` 의 `[3]`(고정 구간의 한계)과 `[8]`(오버플로 없는 백오프)을 먼저 읽자.

## 요구사항

처리 능력을 넘는 요청을 전부 받으면 모두가 느려지다 실패한다. **받을 수 있는 만큼만 받고 나머지는 즉시 거절**하는 부품을 만든다. 시각과 난수는 **인자로 받는다**(그래야 시험이 결정적이다).

| 부품 | 함수 | 하는 일 |
|---|---|---|
| 초당 한도 | `shed_create` / `shed_admit` / `shed_stats` | 1초 고정 구간마다 `tps_limit` 건까지 받는다 |
| 단계별 거절 | `shed_cut_percent` / `shed_pick_reject` | CPU 사용률 → 거절 비율, 비율대로 요청을 거른다 |
| 재시도 백오프 | `backoff_ms` | 지수 증가 + 상한 + 지터 |

## 규칙

| # | 규칙 | 이유 |
|---|---|---|
| 1 | 구간 = `now_ms / 1000`. 구간이 바뀌면 센 개수를 0 으로 | 고정 구간(fixed window) |
| 2 | 시계가 뒤로 가도 새 구간으로 치지 않는다 | 이미 센 것을 잊으면 한도가 뚫린다 |
| 3 | 사용률 구간: 50 미만 0%, 50–69 20%, 70–89 50%, 90 이상 90% | 단계별 거절 |
| 4 | `(seq % 100) < cut` 이면 거절 | 100개 중 정확히 `cut` 개 |
| 5 | 백오프는 `attempt` 가 아무리 커도 **오버플로 없이** `cap_ms` | `base << 100000` 은 정의되지 않은 동작 |
| 6 | 지터 범위는 `[lo, d]`, `rnd` 로 결정 | 재시도가 한순간에 몰리지 않게 |

## 입출력 예시

| 호출 | 결과 |
|---|---|
| limit 5, 시각 0·100·200·300·400·500·1000 | 받음 ×5, 거절, 받음(새 구간) |
| `shed_cut_percent(70)` | 50 |
| `backoff_ms(6, 100, 5000, 0, 0)` | 5000 (6400 이 아니라 상한) |
| `backoff_ms(0, 100, 5000, 50, 500)` | 75 |
