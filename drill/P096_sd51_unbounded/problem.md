# P096 · sd51 unbounded — 무한 자원 할당 — 상한 및 풀로 치환

## 요구사항

서버는 동시에 여러 클라이언트의 접속을 받아들인다.
- 동시 활성 연결 수에는 상한이 있어야 한다.
- 상한을 넘는 요청은 거부해야 한다(서비스 자체는 계속 동작해야 한다).

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **상한 및 풀로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| 연결 요청 횟수 | 외부(클라이언트) | 요청마다 무조건 자원을 늘리는 카운터 증가 지점 |

## 시그니처

```c
int active_count(void);
void reset_active(void);
int handle_connection_bad(void);
int handle_connection_good(void);
```

## 입출력 예시

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 연결 요청 10회 | **활성 연결 10개 전부 생성**(상한 없음) | 요청 횟수만큼 그대로 자원이 늘어난다 — 공격자가 소수의 요청만으로도 자원을 무한정 소진시킬 수 있다 |
| 같은 상황(Good) | **`POOL_MAX`(4)개까지만 수락, 나머지 6개는 거부** | 상한에 도달하면 이후 요청은 실패로 응답하고 자원을 늘리지 않는다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P096` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 상한이 없어 요청한 만큼(10개) 전부 활성 연결로 쌓여야 한다(취약점 재현)
- Good은 POOL_MAX(4)개까지만 수락해야 한다
- 나머지 요청은 거부돼야 한다
- 활성 연결 수는 POOL_MAX를 절대 넘지 않아야 한다
