# P050 · sd05 ldapinj — LDAP 삽입 — 영숫자 화이트리스트로 치환

## 요구사항

사용자 이름(`name`)으로 디렉터리 엔트리를 조회한다.
- 필터는 `(name=<name>)` 형태로 조립한다.
- `name` 은 영숫자만 허용하며 최대 32자.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **영숫자 화이트리스트로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `name` | 외부(조회 폼) | LDAP 필터 문자열 |

## 시그니처

```c
int ldap_lookup_bad(const char *name);
int ldap_lookup_good(const char *name);
```

## 입출력 예시

| 입력 | Bad 결과(매칭 개수) | 이유 |
| :--- | :--- | :--- |
| `alice` (정상) | 1 | 정상 동작 |
| `*` | **3** | 와일드카드로 디렉터리 전체가 노출된다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P050` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 와일드카드로 디렉터리 전체가 노출되어야 한다(취약점 재현)
- 정상 조회는 1건
- Good은 와일드카드를 거부해야 한다
- Good도 정상 조회는 통과
- 다른 정상 사용자도 통과
