# NOTE · P063 sd18 signext (풀고 난 뒤에 보세요)

**원본 글** (읽기 전용, 여기에 복사하지 않음)
- 「[SD] SD18. 의도하지 않은 부호 확장 — 원본 타입으로 직접 검사하도록 치환」 — 시큐어코딩 체화 드릴 (회차 규칙 A/B/C, 변형 요구사항, 모범답안)
- 시큐어코딩가이드: Part 1-4. 정수·타입변환 계열 — 18. 의도하지 않은 부호 확장 (`CWE-194`)

**함정 요약**
- `short s = (short)id;` 를 그대로 두고 `if (s < 0)` 검사만 추가 — 이미 축소 변환이 일어난 **뒤**에 검사하는 것이라 늦다.
- `unsigned` 변환 직전에만 `if (s < 0) return -1;` 을 넣고 원본 `id` 상한(300)은 검사 안 함 — 부호 문제는 막아도, `id` 가 300~32767 사이의 정상 양수 `short` 범위라면 여전히 배열을 벗어난다.
- 이 항목도 SD17처럼 UBSan이 잡아줄 거라 기대함 — 대입에 의한 축소 변환은 구현정의이지 UB가 아니다 — 새니타이저에 기대지 말고 **코드 자체를 정확히** 짜야 하는 항목이다

**한 줄 설명 연습**: "원본 타입으로 직접 검사하도록 치환" — 이 규칙을 내 말로 한 줄로 쓴다.
