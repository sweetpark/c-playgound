# P061 · sd16 nullterm — 널 종료 문제 — 길이 명시 복사와 수동 종료로 치환

## 요구사항

`read()` 로 읽은 것처럼 길이가 고정된(`raw_len`) 바이트 버퍼를 문자열 버퍼(`out`)로 복사한다.
- `raw` 는 널로 끝난다는 보장이 없다.
- `out` 은 항상 널로 끝나야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **길이 명시 복사와 수동 종료로 치환**.

## 시그니처

```c
void copy_raw_bad(const char *raw, char *out);
int copy_raw_good(const char *raw, size_t raw_len, char *out, size_t out_size);
```

## 입출력 예시

| `raw` 상태 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 8바이트를 `\0` 로 채우고 `"hi"` 를 앞에 씀 (정상) | 정상 동작 | 우연히 널 종료가 되어 있는 경우 |
| **정확히 8바이트를 `'A'` 로만 채움(널 없음)** | **힙 버퍼 오버리드로 크래시** | `strcpy` 가 8바이트를 넘어 널을 찾아 계속 읽는다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P061` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 널 종료 안 된 버퍼를 strcpy로 읽으면 경계를 넘어 크래시해야 한다(취약점 재현)
- 정상 널 종료 문자열은 크래시 없이 동작해야 한다
- Good은 out 버퍼가 raw_len을 다 담을 수 없으면 실패를 알려야 한다
- 그래도 out은 항상 널로 끝나야 한다
- 정상 길이는 성공해야 한다
- 복사된 내용이 정확해야 한다
