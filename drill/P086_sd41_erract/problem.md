# P086 · sd41 erract — 오류상황 대응 부재 — 실제 조치 동반으로 치환

## 요구사항

요청을 처리하기 전에 사전 검증 단계를 거친다.
- 사전 검증이 실패하면 잔액 차감이 절대 일어나서는 안 된다.
- 실패 시 호출자는 반드시 실패를 알 수 있어야 한다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **실제 조치 동반으로 치환**.

신뢰 경계:

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| 사전 검증 결과(`rc`) | 내부 검증 로직 | `if (rc != 0)` 블록이 비어 있어 검증 결과와 무관하게 다음 로직(잔액 차감)이 그대로 실행된다 |

## 시그니처

```c
int process_request_bad(int step1_will_fail, int *out_balance);
int process_request_good(int step1_will_fail, int *out_balance);
```

## 입출력 예시

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 사전 검증 실패(`rc = -1`) | **잔액이 그대로 차감되고 함수는 성공(0)을 반환** | `if` 블록이 비어 있어 실패를 감지만 하고 아무 것도 막지 않는다 — 심지어 반환값도 거짓으로 성공을 알린다 |
| 같은 상황(Good) | **잔액은 그대로, 함수는 실패(-1)를 반환** | 실패를 감지한 즉시 `return -1`로 이후 로직 실행 자체를 막는다 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P086` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 내부 단계가 실패해도 항상 성공(0)을 보고해야 한다(실패 은폐 재현)
- Bad는 실패를 감지하고도 아무 조치가 없어 잔액 차감이 그대로 진행돼야 한다(상태 오염 재현)
- Good은 내부 단계가 실패하면 그 실패를 그대로 호출자에게 알려야 한다
- Good은 실패 시 즉시 중단해 잔액이 전혀 바뀌지 않아야 한다
- 정상 경로는 성공을 보고해야 한다
- 정상 경로는 잔액이 정확히 차감돼야 한다
