# P105 · msgq_probe — 메시지 큐를 직접 만들고, 채우고, 들여다보기

> 예상 시간: 30분. `test.c` 의 `[3]`(가득 찰 때까지)과 `[5]`(보낸 쪽이 죽어도 남는다)를 먼저 읽어 보자.

## 요구사항

프로세스끼리 메시지를 주고받는 **System V 메시지 큐**는 커널이 큐를 들고 있다.
"큐가 꽉 차면 어떻게 되나", "받는 쪽이 죽으면 큐는 어떻게 되나"를 코드로 확인하는 작은 도구 여섯 개를 만든다.

| 함수 | 하는 일 |
|---|---|
| `mq_create(qbytes)` | `msgget(IPC_PRIVATE)` 로 큐를 만들고 용량(`msg_qbytes`)을 `qbytes` 로 **줄인다** |
| `mq_send_one(qid, len)` | `len` 바이트 메시지를 **`IPC_NOWAIT`** 로 보낸다. 성공 0, 실패 `-errno` |
| `mq_fill(qid, len, &sent)` | 막힐 때까지 보낸다. 보낸 개수와 멈춘 이유(`-EAGAIN`) |
| `mq_stat(qid, &n, &b, &cap)` | 쌓인 개수·바이트·용량 (`msgctl(IPC_STAT)`) |
| `mq_drain(qid)` | 쌓인 것을 **기다리지 않고** 전부 꺼낸다. 꺼낸 개수를 돌려준다 |
| `mq_remove(qid)` | `IPC_RMID` |

## 지켜야 할 것

| # | 규칙 | 이유 |
|---|---|---|
| 1 | 보낼 때 `IPC_NOWAIT` | 안 쓰면 큐가 찬 순간 `msgsnd` 가 **그 자리에서 잠든다.** 서비스가 멈춘 것처럼 보인다 |
| 2 | 가득 참은 `EAGAIN` | 에러가 아니라 "지금은 못 넣는다"는 신호다 |
| 3 | 용량 계산에 `mtype`(8바이트)는 **포함되지 않는다** | `msg_cbytes` 는 본문 길이의 합이다 |
| 4 | 용량은 올리려면 특권이 필요하다 | 그래서 `qbytes` 가 현재 용량보다 **작을 때만** 설정한다 |
| 5 | 빈 큐에서 `msgrcv` 는 `IPC_NOWAIT` 가 없으면 영원히 기다린다 | drain 은 `ENOMSG` 에서 끝낸다 |
| 6 | 보낸 쪽이 죽어도 큐와 메시지는 남는다 | 큐는 프로세스가 아니라 **커널의 것**이다 |

## 입출력 예시

| 상황 | 결과 |
|---|---|
| `mq_create(4096)` 후 `mq_fill(q, 100, &s)` | `s = 40`, 반환 `-EAGAIN` |
| 이어서 `mq_send_one(q, 96)` | 0 (남은 96바이트에 정확히 맞음) |
| 이어서 `mq_send_one(q, 1)` | `-EAGAIN` |
