# P060 · sd15 writeindex — 검사되지 않은 배열 인덱싱 — 하한·상한 동시 검사로 치환

## 요구사항

사용자가 지정한 "1번째, 2번째, ..." 같은 1-based 위치(`num`)에 값을 쓴다.
- `num` 은 1 이상, 배열 크기 이하만 유효하다.

이미 `solution.c` 에 **Bad 함수가 들어 있다**(취약점을 먼저 관찰하세요). 같은 소재의 **Good 함수만 구현**한다. 치환 규칙: **하한·상한 동시 검사로 치환**.

## 시그니처

```c
void write_at_index_bad(int *arr, int num, int value);
int write_at_index_good(int *arr, size_t arr_size, int num, int value);
```

## 입출력 예시

| `num` (배열 크기 5) | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 5 (정상, 상한) | 정상 동작 | `arr[4]` 는 유효 |
| 10 (상한 초과) | **힙 버퍼 오버플로우로 크래시** | `arr[9]` 는 할당 범위 밖 |
| 0 (하한 미만) | **버퍼 시작 이전 쓰기** | `arr[-1]` 은 배열 앞의 메모리 |

## 제약

- Bad 함수와 `mock_*` 파일(있다면)은 수정하지 않는다. `solution.c` 의 Good 함수만 채운다.
- Bad 는 **실제로 뚫린다**는 것이 시험의 일부다(자식 프로세스로 실행). Good 은 같은 공격을 막고 정상 입력은 그대로 통과시켜야 한다(과잉 차단 금지).
- 경고 0, ASan/UBSan 0 (`-Wall -Wextra -Werror`).

## 통과 기준

`make P060` → `PASS` (실패 시 `FAIL k` 와 어긋난 항목 출력), 경고 0, ASan/UBSan 0. 힌트: `HINT1.md` → `HINT2.md`.

시험이 확인하는 것:

- Bad는 배열 크기를 넘는 인덱스에 쓰면 크래시해야 한다(취약점 재현)
- 유효 인덱스는 크래시 없이 정상 동작해야 한다
- Good은 상한 밖 인덱스를 거부해야 한다
- Good은 0(하한 밖)도 거부해야 한다
- 정상 인덱스는 성공해야 한다
- 쓰인 값이 정확해야 한다
