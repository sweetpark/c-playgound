# NOTE · P041 d3 cfg (풀고 난 뒤에 보세요)

**원본 글** (읽기 전용, 여기에 복사하지 않음)
- 「[D] D3. 자원 잡는 함수 — goto CLEANUP·create·destroy」 — 템플릿 체화 드릴 (회차 규칙, 변형 B/C 요구사항, 채점표, 모범답안)

**함정 요약**
- `p = realloc(p, n)` — realloc 실패 시 **원본 포인터를 잃어버린다** → 확정 누수. `tmp` 로 받고 성공했을 때만 대입
- `CLEANUP` 앞에서 `return ret;` 을 추가로 함 — 그 경로만 해제를 건너뛴다. **출구는 하나**
- 해제 순서를 잡은 순서대로 — 버퍼를 먼저 free 하고 그 버퍼를 쓰는 `fclose` 후처리를 하면 use-after-free
- `_destroy()` 안에서 멤버만 free 하고 객체 자체를 안 함 — 객체 크기만큼 매번 샌다
- 성공했는데 `ret` 을 안 바꿈 — `RET_FAIL` 로 시작했으니 **정상인데 실패로 리턴**된다. 제일 흔한 자책골
- `goto CLEANUP` 이 변수 선언을 건너뜀 — `-Wjump-misses-init` / C++ 에서는 컴파일 에러.
- (B) `CLEANUP` 이 mutex 를 `init` 도 안 한 채 `destroy` 함 — 정의되지 않은 동작.
- (B) 이름 배열은 해제하고 안쪽 문자열은 안 함 — 이름 개수만큼 샌다.
- (C) 쓰기 파일을 `SAFE_FCLOSE` 로 닫음 — 디스크 가득 참 같은 쓰기 오류가 `fclose` 에서 드러나는데 **성공으로 보고**한다.
- (C) 실패 경로에서 `dst` 를 안 지움 — 반쯤 쓴 파일이 남아 다음 실행이 그걸 읽는다
- (C) `fd` 를 `0` 으로 초기화 — `0` 은 표준입력이다. `SAFE_CLOSE` 가 stdin 을 닫아 버린다.

**한 줄 설명 연습**: 이 함수의 가드 → 본 처리 → 단일 출구 구조를 내 말로 한 줄로 쓴다.
